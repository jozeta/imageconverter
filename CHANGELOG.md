## Unreleased

## 1.2.0 (2026-11-15)

- **Updates**: About imageconverter has **Check Now**, a **Check for updates when the app starts** checkbox and a status line ("Checking…", "You're up to date (1.1.0)", "Version 1.2.0 is available" or the error). The first launch asks once *"Check for updates automatically?"* (UserDefaults `updateCheckOnLaunch`, absent until answered); nothing goes online before a yes, and Check Now always works. A launch check is silent when up to date or on an error. A newer release opens a sheet with its notes as plain text, **Install and Relaunch** and **Later**. Only GitHub's latest `jozeta/imageconverter` release is accepted: tag `v` + strict `x.y.z`, newer than the running app, no draft or prerelease, assets `imageconverter-<x.y.z>.zip` and `.zip.sha256`, API answer ≤ 1 MB, downloads over HTTPS from `github.com`, `objects.githubusercontent.com` or `release-assets.githubusercontent.com` (checked on every redirect and the final response), zip ≤ 200 MB and checksum ≤ 1 KB, counted while streaming; an ephemeral session without cookies, cache or credentials, sending only `User-Agent: imageconverter/<version>`. The zip must match its SHA-256, list only names inside one `imageconverter.app` (no `..`, absolute paths or writes through links; checked with `zipinfo` before unpacking), unpack with `ditto` into a fresh temporary folder, have no link leading outside the bundle, carry the release's version and pass `SecStaticCodeCheckValidityWithErrors` (all architectures, strict, nested code) against Developer ID team `6W6TD6P8G3`, identifier `io.github.jozeta.imageconverter`, notarized. Installing is refused outside the packaged app and while a batch or job runs (checked again right before anything moves). The old app goes to the Trash, the new one takes its path, and a failure after that puts the old one back; then the new app is opened and this one quits. Core `UpdatePackage`, `UpdateSignature`, `UpdateReplacer`; app `Sources/Imageconverter/Update/` (`UpdateClient`, `UpdateVerifier`, `UpdateInstaller`, `UpdateController`) and `UpdateViews.swift`.
- **Installer service**: updates are unpacked, checked and installed by an XPC service inside the bundle (`Contents/XPCServices/io.github.jozeta.imageconverter.installer.xpc`) that runs without the App Sandbox, because files a sandboxed process creates are quarantined and can't be opened. It accepts only the containing app signed with the developer's Developer ID (a `-DUPDATE_E2E` build accepts the ad hoc `…updatetest` app, for the end-to-end test), replaces only the app it is inside, takes the zip only from the app's container download folder, redoes every check on its own copy, swaps in the app's folder and removes quarantine from the new app. The app no longer asks for access to the Applications folder (the `installUpdate` folder grant is gone). The unpack is watched: ditto is stopped (SIGTERM, then SIGKILL) once the space actually used (the larger of the folder's allocated size, resource forks included, and the free space the volume lost) is over the cap, since a zip can declare smaller sizes than it inflates to, or once less than 2 GB stays free; what ditto wrote must match the zipinfo listing. The service refuses a version at or below the installed one, opens the download with `O_NOFOLLOW_ANY`, and logs (doesn't fail on) a quarantine mark it can't clear after a good swap; the app gives up after 10 minutes without an answer. `release.sh` refuses `UPDATE_E2E` with a real identity or `--notarize` (and a non-ad-hoc build whose service names `.updatetest`), and requires exactly the app's four entitlements. An offline revocation check says "Couldn't confirm the update's signature right now. Try again when you're online." Leftovers of an interrupted update are removed. `scripts/release.sh` builds, assembles, signs (no entitlements) and checks the service, and accepts extra `swift build` arguments in `SWIFT_FLAGS`; its entitlement checks no longer pipe into `grep -q` (with `pipefail` that could hide a match). Core `UpdateInstallerProtocol`, `UpdateQuarantine`, `UpdatePackage.unpack`/`runWatched`; targets `ImageconverterInstallerKit` (tested) and `ImageconverterInstaller`.
- Update hardening (review fixes): the zip listing is capped before unpacking (20,000 entries, 1 GB unpacked, 8 MB of `zipinfo` output); link entries are compared ignoring case and Unicode normalisation; the signature check enforces revocation checks. Installing is checked before downloading (refused from a translocated or read-only location). The swap stays inside the app's folder: the verified app is copied in as a hidden sibling and checked again, the old app renamed aside, the new one renamed into place (the old one renamed back on failure), and only then is the old one trashed, so no step needs the Trash to undo. "Nothing running" is checked again right before the swap. Later during the download check no longer shows an error. The privacy wording says a check shows GitHub your IP address and standard HTTP headers. `NoNetworkTests` allows networking only in `UpdateClient.swift`.
- Entitlements: `com.apple.security.network.client` (outgoing only, for the update check). `scripts/release.sh` now requires it and fails on `network.server`, and checks that `UpdatePolicy.bundleIdentifier` equals `BUNDLE_ID`. `NoNetworkTests` allows `URLSession`/`URLRequest` and the GitHub API address only in `Sources/Imageconverter/Update/UpdateClient.swift`; anywhere else they still fail the build. Privacy statement, README, SECURITY.md: "No network access except the optional update check and download from github.com"; Help ▸ Privacy… explains what a check sends and lists the update limits. `scripts/screenshots.sh` answers the first-launch question with No.

## 1.1.0 (2026-11-15)

- **Extra outputs**: several files per image in one run. **+ Add output** under the Output format controls adds up to 8 outputs, each with a name, its own format and compression (quality, target or maximum size, smart), a size (same as the main output, longest edge, max width or max height, shrink only, or a percentage, above 100 enlarges), a required name suffix (sanitised; empty or repeated suffixes, compared ignoring case, show an inline error and disable Run) and an optional subfolder template. Each image is decoded and processed once; every extra output is then resized and encoded with its own compression search, one at a time, and written as `<name><suffix>.<ext>` next to the main output, always as a new file (never in place, never trashing anything, `_2` on collisions with any file, original or other output). In overwrite mode the original is replaced once, or trashed after the extra outputs are saved. If the main output fails, its extras aren't written; one extra failing is a note ("Extra output “Thumbnail” failed: …"). Conditions' *Set output* changes only the main output; the new action **Skip extra outputs** leaves them out for matching images, and copies of the original get none. The size line lists every output ("Primary 1.1 MB · Thumbnail 48 KB · Web 620 KB", the same encodes as the batch), the preview's Result name shows a "+2 outputs" chip listing them on hover, reports have a row per extra output under its image (CSV column `output`; counts stay per image, output bytes and Reveal in Finder include every file), jobs record every output on their ledger, and the memory scheduler counts the resized copies. Pipelines, presets and jobs save them (`extraOutputs`; older files load with none, invalid ones are left out with a note). Command line: `--variant "name=thumb,format=jpeg,quality=70,long=400,suffix=_thumb"` (repeatable, replaces the preset's extra outputs; `--dry-run` lists them). Core `OutputVariant`, `OutputPlanner.planVariants`, `BatchRunner+Variants`.
- Failed extra outputs are shown at run level: each one is a failed report row under its image ("Extra output “Thumbnail” failed: …", also when no free name was left), counted in the summary (`RunSummary.extraFailures`, CSV/text totals), written to the error log and the history, added to the end-of-run notice (red) and the *When finished* notification ("· 2 extra outputs failed"), and the command line exits 1. Jobs don't retry them (that would write the main output again as `_2`). The "saved" phrase in the notice and notification compares the main outputs with their originals only. Extra outputs whose settings can't be read (e.g. a newer format) are left out with a note instead of turning into JPEG; repeated output ids in a hand-edited file get new ones instead of dropping valid outputs. Outputs left out on load are now also reported when the app restores its pipeline at launch and in a job's status and error log. A run notification click brings the main window itself forward (reopening it when closed), not the first window that can become main.
- **When finished** setting under Save to in the Output panel: Nothing (default), Reveal in Finder, Notify me, Reveal and notify. Reveal selects the written files in Finder (up to 50 files, otherwise their folders); Notify posts a local notification with the run summary only when the app is in the background, asking for notification permission the first time it is chosen (a note appears when notifications are refused, and goes away when you allow them). A cancelled run says "Run cancelled · converted N", a run where every file failed says "No images converted · N failed" (no Finder window). Clicking a run notification brings the window forward with the Report open. Applies to manual runs and runs started by Services, AppleScript and links; app-wide, not stored in presets (Core `AfterRunAction`).
- Metadata-only edits no longer re-encode JPEG and HEIC files. When an image's resolved pipeline changes only metadata (Metadata step on, no enabled image step after conditions, the output format is the file's own, compression mode Quality), the image data is copied untouched with the new metadata (`CGImageDestinationCopyImageSource`): a JPEG's scan data stays byte-identical, the quality slider is not used, and the EXIF orientation flag is kept instead of rotating pixels. The report says "Metadata only, pixels untouched". The written file is read back and compared with a re-encode of the same metadata; anything the options remove that survived, or a kept or set field that is missing, falls back to the re-encode with the note "Lossless edit couldn't remove …; re-encoded" (or "couldn't write …"). A JPEG copy is rebuilt from an allowlist of segments (the JFIF header with its thumbnail dropped, EXIF with its thumbnail cut off, XMP but not extended XMP, ICC profile, Adobe, the re-encode's IPTC block): Photoshop previews and other APP13 resources, comments, other APPn blocks and data after the image end are dropped, and an unreadable structure re-encodes ("Lossless edit couldn't remove JPEG segments; re-encoded"). No output carries an embedded thumbnail; a HEIC copy with a thumbnail, several images or depth, matte or gain-map data re-encodes. XMP values are compared in full, not only tag names (Core `JPEGSegments`). PNG, TIFF, AVIF and other formats are re-encoded with the note "Re-encoded: lossless metadata edit isn't available for this format". Applies to the batch, "Copy original unchanged" converted to remove metadata, the Privacy panel's Remove these, jobs and the command line; the size estimate uses the same path, and the quality ladder is empty for such images (Core `LosslessMetadata`).

## 1.0.0 (2026-11-14)

First release: a signed and notarized, sandboxed app with the command-line tool inside.

- Final-review fixes: resuming an interrupted batch in the sandboxed app no longer loses images that were added as loose files (Add…, a drop) while saving to a new folder: the run journal also keeps a bookmark of each such file (up to 2 000), resuming reopens them, asks for the folder of any image that still can't be read before the resumed run is planned, and lists images in a folder you don't allow as "couldn't be opened" instead of missing (Core `ResumePlan` checks readability, `AccessPrompt.askToRead`). **Add…** and File ▸ Add Images… do nothing during a run, like drops. Folder Access ▸ Remove and Remove All are unavailable while a batch or job runs. Choosing the same output folder again renews its bookmark. Two watermark steps with the same image path but different bookmarks (an older step and a preset's) both get tried, so the one that opens is used. A file dragged onto a pipeline step row is added instead of being swallowed by the row's reorder target (Core `DropPayload`). The Output hover help no longer says new-folder output is always flat. `scripts/screenshots.sh` passes shellcheck and shrinks screenshots with a Swift script instead of Pillow.
- README screenshots: `scripts/screenshots.sh` launches the DEBUG app with its own settings (`-debugDefaultsSuite readme`) on synthetic sample images (`scripts/make-sample-images.swift`, committed in `docs/screenshots/samples`) and prepared pipelines and jobs, captures each window by id (`scripts/window-id.swift`), and shrinks the PNGs to 400 KB or less (`scripts/shrink-png.swift`, Core Graphics and ImageIO only; over 500 KB is a warning). The README's Screenshots grid and Installation section (zip, build from source, Gatekeeper, command-line tool) are refreshed, and the window-height setting is documented.
- Sandboxed app smoke-test fixes: images and folders opened with the app (dropped on the Dock icon, Finder's Open With, `open -a imageconverter …`) are now added to the batch in the open window (the bundle declares image and folder document types, rank Alternate, so it never becomes the default app); before, each opened file opened a new, empty window and nothing was added. A folder opened this way counts as allowed for the session, like a dropped one. Files, links and Quick Actions that arrive while the app is still launching wait for its main window instead of opening a second one. Help ▸ Folder Access… has **Add Folder…** to allow a folder ahead of time. In the sandboxed app, "doesn't exist or can't be read" and "isn't a folder you can write to" (AppleScript, links) add which files and folders the app can use and where to allow more.
- Conditions, review fixes: a check on a value the file lacks is false whether or not it is negated (only the presence checks match missing values); regular expressions in conditions and in Rename find-and-replace stop after 50 ms (no match / no replacement, note "Pattern took too long"); "within the last N days" counts calendar days (today and the N days before, across daylight-saving changes); watermark images are loaded per image path, so a preset applied by a condition with its own watermark works in the batch; a copied original notes the added keywords or preset image steps it ignores, and an original overwrite mode leaves untouched is never tagged; the subfolder containment check follows symbolic links; report notes drop bidi and other invisible characters; "Apply preset" reads the presets folder of the app, the command line or the job without any process-wide setting; output names give up after `_10000` ("Couldn't find a free name").
- *Overwrite original files* works with the Rename step. The renamed result is written into the original's folder, and the original is moved to the Trash only after the new file is saved; the same name and format still replaces the file in place, and a case-only rename keeps the original name. No other file is replaced: a name taken by an unrelated file, by another image's original in the batch (e.g. `a.jpg` renamed to `b` while `b.jpg` is in the batch) or by another image's new name gets `_2`, `_3`, … The preview name, the batch, conditions (a branch's rename; a renamed "Copy original unchanged" moves the file to its new name, without a rename it stays a no-op), jobs (renamed results are on the ledger as outputs) and the command line (`--overwrite --yes` with a preset's or pipeline's rename) all plan the same way; `--dry-run` marks each overwrite destination "replace" or "replace (original to Trash)". The overwrite note and confirmations say "When the name or format changes, the original is moved to the Trash after the new file is saved." If moving the original to the Trash fails, the new file is listed as written with the warning "Converted, but couldn't move the original to the Trash: …" (no longer as a failure), and a job counts the original as done and the new file as its output, so it isn't renamed again on the next run. The live progress and the image list agree: such a file ends as done, not counted as failed.
- Conditions: many more checks and actions. Every condition has a **Not** switch (saved as `{"not": …}`; older pipelines load unchanged, unknown kinds are dropped). New checks, grouped in the kind menu: Name & location (file name contains / starts with / ends with / is / matches a regular expression, optional Match case, an invalid expression never matches and is shown in the editor; extension list; folder path contains), Dates (date taken from EXIF DateTimeOriginal, else XMP; file created; file modified: before, after, between, within the last N days, in a year, in a month, present), Metadata (named fields: camera make and model, lens, ISO, focal length, aperture, shutter speed, artist, copyright, title, description, keywords, software, plus any allowlisted EXIF/IPTC/XMP key: is, contains, is present, is missing; numbers also more than, less than, at least, at most) and Image (megapixels, aspect ratio wider/taller than or about square, bit depth, color space, embedded color profile, DPI, rotated by EXIF orientation, animated or multi-page). Facts stay header-only and are read lazily (XMP and frame count only when a check needs them; the preview cache re-reads when more is needed). New branch actions, grouped (Steps / Output & files / Metadata / Flow): **Save into subfolder** (rename tokens per folder name, sanitised like file names, no `..` or absolute paths, at most 5 levels; under the output folder or the source's folder; collisions per final folder; ignored with a report note when overwriting), **Add Finder tags**, **Apply a saved preset** (its enabled image steps at the condition's place, its output, and its metadata and rename when on; a missing preset is a report note), **Add keywords** (merged, add mode, the Metadata step's removals stay), **Stop** (later condition steps aren't checked) and **Add a note** (tokens allowed). At most 20 actions per branch. The preview name, the batch, jobs (outputs on the ledger) and `--dry-run` all show the subfolder. Summaries use words only.
- Hover help: resting the pointer on a pipeline item's title (any image step, Metadata, Rename, Output, If … then … else) for 1.5 s opens a box saying what it does, how to use its main settings and a few tips (Core `StepHelp`, app `StepHelpHover`). It closes when the pointer leaves, on click, scroll or Escape, never takes focus, and the summary is also the VoiceOver hint. DEBUG `-debugShowStepHelp <kind>`.
- With no images loaded, controls that need an image are disabled: the preview's Compare picker, the View menu's compare modes and zoom commands, and the privacy chip is hidden. Pipeline editing and presets stay available. The drop zone also refuses drops while a run is in progress.
- Drop images or folders anywhere in the main window, not only on the drop zone: a soft accent border and tint with "Drop images or folders to add them" appear while a file drag is over the window. Step reordering is unaffected, and dropping is off while a run is in progress. DEBUG option `-debugShowDropOverlay`.
- Main window height: collapsing or expanding the pipeline, adding, removing or opening a step and switching Output/Save to modes now animate in one quick ease-in-out motion with the window edge and the content moving together (no jump, flicker or scrollbar flash; the window follows the sidebar frame by frame). With the pipeline expanded the window can be resized vertically: extra height goes between the last step and the Output panel (Output and Run stay at the bottom; there is always a small gap above Output), a shorter window scrolls the steps, and the chosen height is remembered (`expandedWindowHeight`); collapsed, the window still fits the content exactly. DEBUG options `-debugTogglePipelineEvery`, `-debugStepCycle`, `-debugWindowHeight`.
- Conditions use words instead of symbols everywhere: "is more than", "is less than", "is at least", "is at most" in the editor and the step summary (`longest edge is more than 2048 px`, `file size is less than 500 KB`), orientation reads "is portrait", the location test "has location / has no location", and the match picker "Match all of these / Match any of these".
- Adjust sliders: double-click a slider to reset it to 0, and a slider's filled track is blue only while its value is not 0 (grey at neutral).
- `scripts/release.sh` builds a universal, sandboxed `imageconverter.app` (hardened runtime, App Sandbox with user-selected files and bookmarks, no network) with the command-line tool at `Contents/Helpers/imageconverter`; Info.plist from `VERSION` and the Services/AppleScript/URL fragments; ad hoc signing by default, `--notarize` with a Developer ID and a notarytool keychain profile. `scripts/install-cli.sh` links the tool into `~/.local/bin`. CI builds and verifies the bundle. The bundle is assembled in a temporary folder and moved into `dist/` only when signed and verified (older zips there are removed); `VERSION` must be plain `x.y.z`; the single-architecture fallback is used only when the toolchain can't build universal binaries; a rejected notarization prints the notary log and fails; the copyright comes from the last commit's year and `LICENSE`. README: how to open an ad hoc build on another Mac.
- Resize presets: the Presets menu is now grouped (Print: Photo cm, Photo in, Paper; Web; Devices & wallpapers; App & web assets; Social media; Resolutions) with 60 more sizes, each shown with its size, including ten more social formats. Print presets use the new **Print sheet** mode (300 dpi), which fits each image into the sheet in its own orientation (landscape into 15 × 10 cm for 10 × 15 cm); older presets and pipelines load unchanged.
- More ▸ Clear All… (next to Save) asks "Clear all images and pipeline steps?" and, on confirm, empties the image list and resets the pipeline to a fresh default with "None (ad hoc)" selected, no unsaved-change dot and the preview, zoom, compare and report cleared. Saved presets and the Save to setting are kept. Disabled while a run is going or files are being added.
- Sandbox file access: before a run (Run, Finder Quick Actions, AppleScript, links, Resume) the app works out which folders it needs and hasn't been given (Core `AccessNeeds`: same-folder and overwrite need each image's folder, new-folder only the output folder plus the folders of images it can't read; symlinks resolved, case as the volume compares names, a folder inside another needed one asked once) and asks for each with an open panel opened on that folder ("imageconverter needs access to “Photos” to save next to the originals. Choose this folder (or one that contains it) to allow it.", button **Allow**), re-checking after every answer; Cancel stops the run with a toast (scripts and Quick Actions get "imageconverter wasn't allowed to use a folder…"). Only when sandboxed (`Sandbox.isActive`; DEBUG `-debugSimulateSandbox`). Allowed folders are remembered as app-scoped security-scoped bookmarks (UserDefaults `folderGrants`, at most 200, least recently used dropped), opened at launch and kept open; folders dropped or added count for the session. Help ▸ Folder Access… lists them with Remove and Remove All (DEBUG `-debugShowFolderAccess`). The output folder (`outputFolderBookmark`) and watermark images (`ImageWatermark.bookmark`, carried by presets, templates and the saved pipeline; older files still load) keep bookmarks and follow moved files; a watermark whose bookmark no longer opens says "Couldn't open the watermark image — choose it again". The run journal keeps bookmarks of the sources' outermost folders and the output folder, and Resume opens them again or lists the folders it can't. The command-line tool reads presets and jobs from the sandboxed app's container when it exists, else from Application Support; `--data-dir DIR` overrides. A remembered folder, the output folder or a journal folder counts only when its security-scoped access really started (a bookmark that resolves without its scope is shown as "Allow again"); a folder chosen in the panel that doesn't contain the needed one is not remembered and the folder is asked again ("The folder you chose doesn't contain …"); duplicates of the same folder are merged; bookmarks from presets, templates, jobs and the journal are resolved without mounting volumes or showing UI and capped at 64 KB; stale watermark bookmarks are renewed in the edited pipeline (a selected preset shows unsaved changes, its file isn't rewritten); the new-folder readability check runs once per folder off the main thread; Quick Actions report a refused folder once.

Resuming an interrupted overwrite batch leaves alone originals that were already replaced, and each finished image is recorded the moment it is written. The same file added twice (loose and through its folder) is listed and converted once. - Batch engine (Core): `BatchRunner.run` takes an optional `BatchControl` (pause, so no new file starts while running files finish; resume; move files to the front of the queue; low-memory mode with 2 workers, a quarter of the memory budget and no up-front decode caching) and an `events:` callback with each file's stages (queued, decoding, processing, encoding, writing, done, failed, skipped, cancelled, with sizes and duration); `progress:` works as before.
