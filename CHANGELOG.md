# Changelog

All notable changes to imageconverter are listed here, newest first.

## Unreleased

- Preview comparison: a **Compare** control (and View › Side by side / Split / Difference / Single, ⌘1…⌘4) with Split (one image, a draggable divider wiping between Before and After, position remembered, ← / → when focused), Difference (the encoded result's difference from the original amplified ×4, with PSNR, mean and maximum error; "Not available: the size changes" when the size differs) and Single (After large; hold Space over the image or press B to see Before). All modes share the zoom. A light/dark checkerboard is drawn behind images in the preview, the zoom and the thumbnails. The batch under the preview can be a Filmstrip, a Grid (arrow keys move in two dimensions, resizable height) or a List (name, dimensions, file size, the selected image's estimated output, and written/skipped/failed after a run); the mode is remembered. **Compare quality…** (formats with a quality) shows four tiles at 40/60/80/95 % with size and change, at the shared zoom; clicking one sets the output quality. Difference and quality images are kept for the selected image only.
- Command-line tool: `imageconverter convert` (preset or pipeline JSON file, `--out`/`--same-folder`/`--overwrite --yes`, `--format`, `--quality`, `--max-size`, `--resize-long`, `--strip-gps`, `--strip-all`, `--report`, `--dry-run`, `--quiet`/`--json`), `presets list`, `jobs list|run NAME`, `--version`, `--help`; exit codes 0/1/2/3. Built as the `imageconverter-cli` product (parser and commands in the `ImageconverterCLIKit` library). Core gets `AppInfo.version` (a test keeps it equal to `VERSION`) and `PipelineFile` (hardened pipeline file reads). README has a "Command line and Shortcuts" section. `--dry-run` uses the batch's own planning (`BatchRunner.plan`), Ctrl-C cancels cleanly (exit 130), unsupported flags warn, missing inputs are reported and counted, short options and flag-as-value are usage errors.
- Metadata editor: collapsible groups Remove (all with a Keep checklist, location, camera, author, thumbnail, IPTC, XMP), Describe (title, artist, copyright with a © button, description, keywords as tokens with Add/Replace), Date (keep, set, shift, file dates), Location (keep, remove, set with validation) and More fields (allowlisted EXIF/IPTC/XMP rows), plus a Templates menu (apply, save as, delete). Also used in condition branches. Location Set removes the location until its fields are valid; custom rows with an empty value are ignored.
- Watermark editor: Rotation slider (−180…180°) with 0°/−45°/45°/90° buttons; Layout Single/Tiled (Spacing 0…400 %, Stagger rows; the position grid and margin are disabled when tiled); Shadow (colour, blur, offset; text and image) and Outline (colour, width; text) toggles; an **Insert** menu with every token and a live line showing the text for the selected image (built from its header and the Metadata step the same way the batch does); **Choose image…** accepts SVG and shows why a file is refused; a **Templates** menu (Apply ▸, Save as template…, Delete ▸ with confirmation) with a name sheet like "Save as preset". The editor is split into `WatermarkEditor.swift`, `WatermarkControls.swift`, `WatermarkTemplatesMenu.swift` and `WatermarkThumbnail.swift`.
- SVG watermarks (Core): Illustrator-style exports now load. One standard SVG 1.0/1.1 doctype (no internal subset) before the root is dropped; `<style>` sheets with only `.class`, `#id` and element selectors (comma lists) setting presentation properties (fill, stroke, opacity, fonts, …) are inlined as attributes that then pass the same allowlist and reference checks (later rules win, existing attributes win over CSS); anything else in the CSS (at-rules, combinators, pseudo-classes, escapes, `!important`, links) refuses the file. Each `<style>` is parsed on its own, each rule's declarations are stored once, and at most 2 000 selectors and 20 000 selector × declaration pairs are accepted, so a small file can't use a lot of memory. `url (` with spaces is treated as `url(` everywhere, and the doctype keyword must be followed by XML whitespace. `rgb()`, `rgba()`, `hsl()` and `hsla()` with plain numbers are allowed in style values. The built-in template is now named "Tiled diagonal (−30°, 15 % opacity)". Refusals now say why: embedded images or links to other files, unsupported features (scripts, animation or advanced styling), too large (over 1 MB), or not a valid SVG.
- Condition editor: **+ Add step › If … then … else** adds a condition step; its editor has Match all/any, up to 10 condition rows (kind, comparison, value with px or KB/MB, format, yes/no, orientation, camera text) and Then / Else action lists with their own **+ Add** menu (image steps, Set output…, Set metadata…, Set rename…, Copy original unchanged, Skip file), the usual step editors inline, and drag (or Move Up/Down) reordering. The preview header shows the branch the selected image takes and "Copied unchanged" / "Skipped by a condition"; the preview's name and the Rename example use the counter number the batch would give (images a condition skips before it take none; facts are read off the main thread and cached per file version). The run notice and the Report count files skipped by a condition apart from failures ("Converted 20 · 3 skipped by conditions · 1 failed").
- Conditions (Core): an if / then / else step resolved per image from the source file's facts (header only, plus a ≤ 256 px scan when a condition asks about transparency): longest edge, width, height, file size, format or file type, transparency, orientation, GPS location and camera make/model, matched all or any (1–10 per step). Branches add image steps (no nesting), override the output, metadata or rename for that image, copy the original unchanged (atomic, no decode; a no-op when overwriting) or skip it (counted as skipped, not failed, with no counter number). The batch plans each item's own format and extension; preview, size estimate, quality ladder, rename and memory scheduling use the resolved pipeline; reports and jobs count skipped files (a job doesn't re-check a skipped or copied file until it changes; job reports count unchanged files separately). Facts are read four files at a time; the transparency scan never decodes an image over the pixel limit. A copy is named from the source itself (`{width}`/`{height}`, `{ext}`, `{format}`), and its size estimate is the file size without decoding. Skipped files are never an output target. Invalid conditions in presets are dropped on load, and a step with none left or more than 10 is dropped.
- Jobs (Core): saved jobs (input folders, recursive or not, output, a copy of a pipeline or a linked preset whose current pipeline is used at run time, manual / watch / schedule every ≥ 5 min, optional report) stored as `jobs/<id>.json`; a per-job ledger of processed files (`jobs/<id>.ledger.json`, path + size + modification date, at most 100 000 inputs and 100 000 outputs, oldest dropped) so a file is processed once unless it changes (a failing file is retried on the next runs and given up after 3 attempts until it changes; the report says so once), scheduled and manual runs leave files that changed in the last 2 s or can't be read yet for the next run, files the job wrote are never inputs and an output folder inside an input folder is never read; a folder watcher (FSEvents) that waits until a new file's size and date are unchanged for 2 s and ignores hidden and temporary files; and a report file (`imageconverter-report-<date>.csv`, `.json` or `.txt`, with totals) written next to the outputs, CSV protected against formula injection. The Jobs window arrives in a later update.
- Watermark options (Core): rotation (−180…180°, clockwise, about the mark's centre; the rotated box keeps the margin), a tiled layout covering the whole image (spacing 0…400 % of the mark, optional stagger), a drop shadow (text and image) and an outline drawn under the text, dynamic text tokens `{filename}`, `{filename.ext}`, `{date}`, `{date:FORMAT}`, `{year}`, `{copyright}` and `{artist}` (from the Metadata step when it sets them, empty when it removes them (including IPTC-only values when it removes IPTC), else from the file; batch, preview and size estimate render the same text), SVG watermark images (at most 1 MB of UTF-8; only shapes, paths, gradients, clip paths, masks, patterns and text are accepted, with links to `#id` only: style sheets, classes, images, scripts, animation, doctypes, other encodings, reference cycles and files that expand to more than 10 000 shapes are refused; the file is parsed and re-written before it is drawn, and nothing is ever fetched), and watermark templates with three built-ins (© corner, Tiled diagonal at −30°, Filename + date). The outline and shadow count towards the margin. Watermark text is now always cleaned: control, bidi and zero-width characters are removed, the ends trimmed and the text cut to 200 characters. Older saved pipelines load unchanged otherwise; the editor arrives in a later update.
- Rename editor: Prefix and Suffix fields, Remove spaces, Special characters (Keep, Replace with `-`/`_`/`.`/nothing, Remove) and Case pickers, the new tokens in the Insert menu plus three quick patterns (Date + counter, Camera + date, Name + size); the live example reflects every option. The editor moved to `RenameEditor.swift`.
- Rename options (Core): prefix and suffix, remove spaces, special characters (keep, replace with `-`/`_`/`.`/nothing, or remove; Unicode letters stay), case styles (lower, upper, camel, Pascal, snake, kebab, title), and new tokens `{focal}`, `{aperture}`, `{shutter}`, `{datetime}` and `{seq}`. Find and replace runs first, then prefix/suffix, spaces, characters and case. Older saved pipelines load unchanged; the editor arrives in a later update.
- Resize editor: grouped mode picker (Pixels, Scale, Print) with longest edge, shortest edge, minimum size, percentage and physical size (cm/in at a DPI); clearer fill labels; a Presets menu (social media, resolutions); resampling picker; Set DPI. Crop: all common aspect ratios in the menu.
- Output row: a Compression picker (Quality, Target size, Maximum size, Smart) with a size field in KB or MB (1 KB = 1000 bytes; invalid input keeps the previous value), Progressive toggle for JPEG, Optimise PNG toggle, AVIF in the format list; the size estimate (and the preview's Size row) shows the chosen quality ("at 74 %") and explains an impossible maximum size.
- Metadata editing (Core): set a title, keywords (added to or replacing the file's own; repeats ignoring case dropped, at most 64 of up to 64 characters), the GPS position (validated, written with N/S/E/W and altitude references), the date taken (set, or shifted by seconds; a file without a date keeps none) and allowlisted EXIF, IPTC and XMP fields; optionally set the written file's creation and modification dates to the date taken (or the original's dates). New removals: author, embedded thumbnail, IPTC, XMP, and fields to keep when removing everything (copyright, author, date taken, camera info, location). The file's XMP is now kept and cleaned with the same rules (removing everything or the location also clears it there). Older saved pipelines load unchanged; the editor arrives in a later update.
- Geometry steps (Core): rotate/flip takes any angle (−180…180°, clockwise) after the 90° turns and flips, either expanding the canvas (white or transparent corners) or cropping to the largest centred rectangle with the original aspect ratio (straighten); a Perspective step with vertical and horizontal keystone (cropped so no empty corners show) and automatic straightening of a detected document or screen (Vision; when none is found the image is left unchanged and the report and size estimate say "No document edges found"); a Trim step that removes transparent, single-colour or edge-colour borders with a tolerance and optional padding (a blank image is left as it is); and an aspect-ratio canvas mode that grows the canvas to a ratio without cropping. Older saved pipelines load unchanged.
- Geometry editors: Rotate / flip gets an Angle slider (−45…45°) with a field for −180…180°, a Fill corners (white, transparent or a colour) / Crop to fit (straighten) choice, and "Mirror (flip horizontally)" / "Flip vertically" toggles; new Perspective (Auto toggle, vertical and horizontal sliders, reset) and Trim (transparent, colour or edge colour, tolerance, padding) editors; the Canvas editor's Ratio mode has the aspect menu (1:1 … 3:4, Custom) and an anchor.
- Resize model (Core): scale by percent, longest or shortest edge, a minimum size (only enlarges) or a print size in inches or centimetres at a DPI (percent and print size ignore "don't enlarge"; a print size with both sides fits inside, keeping the aspect ratio); a choice of resampling (Lanczos by default, also bicubic, bilinear and nearest neighbour) that keeps colour space, bit depth and opacity; an optional DPI written into the file without resampling (the last resize step with one wins, but a print size's DPI is kept when only DPI-only steps follow); fill-and-crop scales only the kept part of the image; crop aspect presets (1:1 … 21:9) and social media and screen resolution size presets. Existing resize steps keep working and now resample with Lanczos.
- Compression report: the size estimate and the preview's Size row show the change ("−74 %"), the after-run toast says how much was saved, and a Report section in the sidebar lists totals, skipped files with reasons, notes and before → after per file.

- Compression modes (Core) for JPEG, HEIC, JPEG 2000 and AVIF: quality, target size (highest quality that fits, with a note when even the lowest quality is too big), maximum size (lowers the quality only when needed; the file is skipped if it can't fit) and smart (the lowest quality that still looks the same, by SSIM). The size estimate uses the same search; for PNG it skips the optimisation and says the optimised file may be smaller.
- Metadata and Rename are optional steps added from "+ Add step" (under "Always last"), no longer in every new pipeline; the "Always last" label shows only when one is used. Every pipeline row now has a trash icon (red on hover or keyboard focus) instead of the cross.
- Adjust step: exposure, brilliance, highlights, shadows, contrast, brightness, black point, saturation, vibrance, warmth, tint, hue, sharpness, definition and noise reduction, as sliders in three groups (Light, Colour, Detail) with a reset per group and double-click on a label to reset one; rendered with Core Image, keeping each image's colour space, bit depth and transparency.
- Preview zoom: pinch on the trackpad to zoom the before and after images together (up to 800 % actual pixels), pan with two fingers or a drag, double-click for fit ↔ 100 %, and View › Zoom In (⌘+/⌘=), Zoom Out (⌘−), Zoom to Fit (⌘0), Actual Size (⌥⌘0). Zoomed in, the full-size original and the encoded result are shown so encoder artifacts can be compared.
- Window: grab handles on the panel edges replace the "Show/Hide preview" and "Collapse" buttons (also View > Hide Preview ⌥⌘P and Collapse Pipeline ⌥⌘L); the window resizes smoothly when the preview or the pipeline is toggled. With the preview hidden the window is exactly the sidebar's size; with it open the window can be resized (at least 780 × 560 pt) and the sidebar panel stretches to its height, so there is no empty space around the panels. Full screen is off for the main window.
- Pipeline rows: drag handle with an insertion line replaces the actions menu (Move Up/Down stay in the context menu and as accessibility actions), a small remove button, "+ Add step" above the steps (new steps start collapsed), switched-off steps collapse and cannot be expanded, and tighter spacing.
- Output row: a "Save to" dropdown replaces the Settings window (⌘, is gone), an "Original → about" size estimate, a Rename step that is greyed out while overwriting, and find and replace (plain or regular expression) in the Rename step. The same-folder suffix defaults to `_new` and is added only when the output would have the original's name.
- Preview and preset fixes: a failed preview no longer shows the previous image, ⌘S is disabled while running, preset names ignore look-alike spaces, skipped preset files give specific reasons, and images whose originals were trashed are removed with a notice.
- Preview: the one-line info is now an Original | Result table (name, folder, dimensions, size with a live estimate); during a run the progress bar and Cancel sit above it (the sidebar keeps them when the preview is hidden).
- Presets (save, save as, rename, delete, reset; three built-ins) and a collapsible before/after preview with a filmstrip of the batch.
- Watermark fixes: an unreadable watermark image now fails the batch immediately without decoding the photos, large logos are downsampled on load (4096 px), tall glyphs and emoji stay inside the watermark's box, line breaks in the text become spaces, image watermarks default to 20 % size when loading older settings, and an empty text shows a hint.
- Watermark step: text (font, colour) or image (e.g. a logo), with position, size relative to the image, opacity and margin.
- Metadata step (remove location, camera details or everything; set artist, copyright and description) and Rename step with tokens ({date}, {camera}, {counter:000}, …) and a live example.
- Wide-colour (Display P3) photos keep their colour when resized and saved as JPEG.
- Pipeline steps: resize, crop, rotate/flip, canvas/padding and color profile; steps can be reordered, switched off and removed; the pipeline is kept between launches. Large images are scheduled by memory use; file types macOS can't read (e.g. SVG) are ignored when adding folders.
- Fixes from the milestone 1 review: correct progress count, large folder drops no longer freeze the window, menu commands (Add Images… ⌘O, Run ⌘R, Cancel Run ⌘.), a missing output folder is asked for again.
- Batch conversion: drop images or folders, choose JPEG/PNG/HEIC/TIFF (and GIF/BMP/JPEG 2000 where available), quality, three output modes, progress and cancel; unreadable files are skipped and listed.
- Design agreed: batch pipeline (resize, crop, rotate/flip, canvas, color profile, watermark,
  metadata, rename, output format), presets, layout with collapsible pipeline and preview. See
  `docs/superpowers/specs/2026-11-13-imageconverter-design.md`. README and CLAUDE.md updated.
